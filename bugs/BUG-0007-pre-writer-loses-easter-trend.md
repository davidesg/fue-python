## Summary

This one is **not in this package**: it is in fue C, and it was found from here
while fixing BUG-0006. fue C's `.pre` writer (`fue.c:2958-3077`) emits only
**seven** of the nine deterministic keywords it can read:

* **`easter`** has no branch at all — nothing is written.
* **`trend`** has a branch that tests for `"time"` — a word the *generator*
  (`fue.c:396`) does not accept — and writes it to `texputv`, the LaTeX file,
  instead of `preputv`. Nothing can produce a `time` variable the generator ever
  understood, so the branch is dead and `trend` is lost too.

The type's line comes out **empty**. Re-reading that `.pre`, the missing word is
taken for a *non-standard* variable, so **fue C does not reproduce its own
model** — and it does not complain, because an unknown keyword is not an error
there.

## Impact

The `.pre` is the program's continuity contract: its seeds *are* the last
iteration's estimates, and the whole pipeline (fue → drtran → the network) is
built on re-reading it. For any model with an Easter or trend variable that
contract is broken, and has been since fue 1.01 — the writer has emitted the same
seven keywords in every version.

Measured on a synthetic monthly AR(1), fitting and then feeding fue C its own
`.pre`:

| variable | fue C | re-reading its own .pre |
|---|---|---|
| `easter` | −300.088544 | **−263.317088** |
| `trend`  | −299.978101 | **−263.317088** |
| `alter`  | −299.866238 | −299.866238 (ok) |

Both collapse to the same −263.317088: the value with the variable effectively
gone. Any `.pre` regenerated by fue for such a model has silently lost it.

## Reproduction

```sh
fue T_easter eml        # fits, writes T_easter.pre
cp T_easter.pre R.inp
fue R eml               # -263.317 instead of -300.089
grep -A1 'Number of deterministic' T_easter.pre   # the type line is empty
```

## Root cause

`fue.c:3050` — `strcmp(dumstrg, "time")` where the generator expects `"trend"`,
writing to `texputv` rather than `preputv`; and no `easter` branch anywhere in the
writer chain, which has no final `else` either.

## Fix

Applied in the fue C repo (`fue-1.13.1/src/fue.c`): an `easter` branch that writes
`easter`, and the dead `"time"` branch replaced by `"trend"` writing to `preputv`.

Known and **not** fixed here: the same writer chain has no branch for
non-standard variables either, so their name line is lost the same way. Left
alone because a non-standard variable also needs its data columns written, which
is a larger question than this fix.

## Validation

Round-trip restored, exactly:

| variable | fue C | re-reading its own .pre | dif |
|---|---|---|---|
| `easter` | −300.088544 | −300.088544 | 0.00e+00 |
| `trend`  | −299.978101 | −299.978101 | 0.00e+00 |

Guarded from this side by `tests/test_bug_0006_deterministic_types.py::
test_los_nueve_deterministas_homologan_con_fue_c`, which asserts the keyword
survives into the `.pre` and compares likelihoods at fue C's own optimum. fue C
has no test battery of its own, so this is where the regression protection lives.
